Guide de test — Cantine OVAGRI

Semaine de démonstration du 9 au 14 novembre 2026 · horloge de départ : mardi 10/11, 20:30

Les données de test sont créées par manage.py demo_week. Tout ce qui précède l'heure de départ a été « vécu » par l'application avec ses vraies règles : menus publiés, réservations et annulations, verrouillage à minuit, finalisation, scans, absences, notifications et journal d'audit.

Lancer l'application

Dans cmd, depuis le dossier de l'application. Régler l'horloge d'abord, puis ouvrir les 3 fenêtres :

backend\.venv\Scripts\python.exe backend\manage.py dev_clock set 2026-11-10 20:30
start "backend" cmd /k "cd backend && .venv\Scripts\python.exe manage.py runserver"
start "scheduler" cmd /k "cd backend && .venv\Scripts\python.exe manage.py run_scheduler"
start "frontend" cmd /k "cd frontend && npm run dev"

Ouvrir http://localhost:5173. Le bandeau orange « Horloge de test » affiche l'heure simulée.

Changer l'heure

Depuis le dossier de l'application (le planificateur applique les changements tout de suite), puis rafraîchir la page :

backend\.venv\Scripts\python.exe backend\manage.py dev_clock set 2026-11-11 08:30
Avancez toujours dans l'ordre des étapes. Revenir en arrière ne défait pas ce qui s'est passé : un menu verrouillé reste verrouillé, un repas servi reste servi.

Étape 1 — Mardi 10/11, 20:30 (heure de départ)

dev_clock set 2026-11-10 20:30

Employé

  1. La cloche affiche « Pensez à réserver ». En haut : « Solde : 6.000 TND ». Chaque jour ouvert indique « Réservations jusqu'au … ».
  2. Mercredi : « Réserver le menu 2 » → solde 3.000 TND ; la cloche marque le rappel « Déjà traité » ; le QR code apparaît dans « Mes réservations » avec « Menu 2 ».
  3. Jeudi : « Prendre ce menu à la place » → le choix change, le solde ne bouge pas.
  4. Jeudi : « Annuler (remboursé : 3.000 TND) » → solde 6.000 TND. Réserver de nouveau.
  5. Vendredi (3.500 TND) : « Solde insuffisant », boutons désactivés.
  6. « Mon solde » : l'historique, avec le solde après chaque mouvement.

Scanner — Caisse et liste du jour

  1. « Caisse » : rechercher « employe » → « 10 TND » → « Enregistrer » → confirmer → solde 13.000 TND (notification « Solde rechargé »).
  2. Retour employé : réserver vendredi → solde 9.500 TND.
  3. « Liste du jour » : menu, statut, heure de service ; filtres, recherche, « Exporter (CSV) ».
  4. « Encaissements » : la recharge de 10 TND apparaît, avec le total « Argent à remettre ». « Imprimer » → la feuille de remise (chaque recharge, total, montant compté, deux signatures).

Direction

  1. « Caisse » : « Corriger le solde » (ex. -5, motif) — le scanner n'a pas ce bouton.
  2. « Encaissements » : le total du jour par personne ; la correction de -5 est comptée, avec son motif. Changer de jour avec ‹ ›, « Exporter (CSV) ».
  3. « Finalisation » : réservations par menu ; « Prix du jour » de samedi modifiable.
  4. « Rapports » : présence par employé du mois (réservés, servis, absences, pas encore servis, dépensé) ; cliquer un employé pour voir ses jours.

RH — Comptes

  1. Onglet « En attente » : Sarra Bouzid et Omar Tlili, « Matricule à saisir ».
  2. Approuver Sarra avec EMP-2001 → refusé (déjà utilisé). Puis EMP-2101 → approuvé : sa notification passe en « Déjà traité » pour tous les RH.
  3. Refuser Omar avec un motif.
  4. Onglet « Suspendus » : réactiver Riadh Hamdi.

Chef

  1. « Plats » : 17 plats ; ajouter un plat avec photo.
  2. « Planning » : samedi 14 → « Modifier les plats » → onglet « Menu 2 » → « Publier ». Composer et publier lundi 16 : le rappel « Menus à publier » passe en « Déjà traité ».
  3. Enlever le menu 2 de jeudi → refusé : des employés l'ont réservé.

Admin

  1. Changer le rôle d'un employé (Comptes → Rôle).
  2. « Paramètres » : passer le rappel des employés à 19:30 → « Enregistrer » ; la page « Notifications » affiche « À 19:30, si vous n'avez pas encore réservé… ». L'exemple en bas des délais montre les heures d'un vrai jour.
  3. Mettre la clôture des réservations à 0 jour, 11:00 → refusé : « Les réservations doivent fermer avant l'heure de finalisation ».
  4. Remettre les valeurs d'origine (rappel 20:00) avant de passer à l'étape 2 : le reste du guide suppose les horaires par défaut.

Étape 2 — Mercredi 11/11, 08:30 : finalisation

dev_clock set 2026-11-11 08:30
  • Employé : mercredi n'est plus annulable (réservations closes à minuit).
  • Direction : « Assiettes à confirmer ». Écran « Finalisation » : un nombre par menu (réservations + 10 % chacun) → confirmer. Le rappel passe en « Déjà traité » pour toute la Direction.
  • Chef : « Nombre d'assiettes » avec le détail par menu.

Étape 3 — Mercredi 11/11, 10:05 : après l'heure limite

dev_clock set 2026-11-11 10:05
  • Direction : le nombre d'assiettes ne peut plus être changé. Si mercredi n'avait pas été confirmé, il a été finalisé automatiquement (réservations + 10 %).

Étape 4 — Mercredi 11/11, 12:30 : le service

dev_clock set 2026-11-11 12:30

Scanner (téléphone ou PC)

  1. Scanner le QR de mercredi de l'employé de test → « Repas validé », « Menu 2 » en gros avec ses plats (l'assiette à servir), « Payé par le solde ».
  2. Le scanner une deuxième fois → « Repas déjà servi » (rouge).
  3. Scanner le QR de jeudi → « Ce code n'est pas pour aujourd'hui ».
  4. Recherche manuelle : taper « Ben Ali » → « Valider la présence » pour Mohamed Ben Ali.

Étape 5 — Mercredi 11/11, 15:05 : absences

dev_clock set 2026-11-11 15:05
  • Avant 15:00, « Liste du jour » affiche « Pas encore servi » ; après, les réservations non scannées passent en « Absent ». Le repas reste payé.
  • Direction : « Rapports » → les absences de mercredi apparaissent, le taux d'absence ne compte que les journées terminées.

Étape 6 — Vendredi 13/11, 12:30 : le prix du jour

dev_clock set 2026-11-13 12:30

Jeudi et vendredi sont finalisés automatiquement en passant 10:00 (si vous ne l'avez pas fait).

  • Scanner : scanner le QR de vendredi → « Payé par le solde (3.500 TND) ». Rien à encaisser : il n'y a plus de paiement au comptoir, tout passe par le solde.
  • Direction : « Encaissements » de mardi 10/11 → le même total que la feuille imprimée par le scanner.

Fin des tests

backend\.venv\Scripts\python.exe backend\manage.py dev_clock reset

L'horloge revient à l'heure réelle ; les données restent.

Recommencer la démo depuis le début

Sur le PC de présentation uniquement (base de démonstration) : fermer les 3 fenêtres, puis depuis backend :

del db.sqlite3
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py demo_week
Ne jamais supprimer db.sqlite3 sur une base contenant de vraies données.
