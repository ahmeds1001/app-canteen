Guide de test — Cantine OVAGRI

Semaine de démonstration du lundi 30 novembre au samedi 5 décembre 2026 · horloge de départ : mardi 1/12, 20:30

Les données de test sont créées par manage.py demo_week. Tout ce qui précède l'heure de départ a été « vécu » par l'application avec ses vraies règles : menus publiés, réservations et annulations, clôture à minuit, finalisation, scans, absences, notifications et journal d'audit. Chaque résultat attendu ci-dessous a été vérifié en rejouant le guide sur une copie de la base (5 novembre 2026).

Préparer la semaine de test

Dans cmd, depuis le dossier de l'application, une seule fois :

backend\.venv\Scripts\python.exe backend\manage.py demo_week

La commande ajoute la semaine du 30 novembre (rien n'est effacé), remet le solde de l'employé de test à 15 TND avant la semaine, ajoute deux inscriptions en attente et règle l'horloge de test sur mardi 1/12, 20:30. Si la semaine existe déjà, elle ne change rien et remet seulement l'horloge.

Paramètres par défaut. Le guide suppose les valeurs d'origine de l'écran « Paramètres » : réservations jusqu'à 23:59 la veille, finalisation à 10:00, service de 12:00 à 15:00, rappel du soir à 20:00, marge de 10 %. Vérifiez-les avec le compte admin avant de commencer.

Lancer l'application

Ouvrir les 3 fenêtres (l'horloge a déjà été réglée par demo_week) :

start "backend" cmd /k "cd backend && .venv\Scripts\python.exe manage.py runserver"
start "scheduler" cmd /k "cd backend && .venv\Scripts\python.exe manage.py run_scheduler"
start "frontend" cmd /k "cd frontend && npm run dev"

Ouvrir http://localhost:5173. Le bandeau orange « Horloge de test » affiche l'heure simulée. La cloche peut contenir des notifications des semaines précédentes : commencez par « Tout marquer comme lu » sur chaque compte.

Changer l'heure

Chaque étape commence par sa commande (depuis le dossier de l'application), puis rafraîchir la page. Le planificateur applique tout de suite ce qui est dû à cette heure.

Avancez toujours dans l'ordre des étapes. Revenir en arrière ne défait pas ce qui s'est passé : un menu clôturé reste clôturé, un repas servi reste servi.

Étape 1 — Mardi 1/12, 20:30 (heure de départ)

backend\.venv\Scripts\python.exe backend\manage.py dev_clock set 2026-12-01 20:30

Employé

  1. La cloche affiche « Pensez à réserver » pour mercredi 2 décembre. En haut : « Solde : 6.000 TND ». Chaque jour ouvert indique « Réservations jusqu'au … ».
  2. Mercredi : « Réserver le menu 2 » → solde 3.000 ; le rappel passe en « Déjà traité » ; le QR code apparaît dans « Mes réservations » avec « Menu 2 ».
  3. Jeudi : « Prendre ce menu à la place » (menu 2) → le choix change, le solde reste 3.000.
  4. Jeudi : « Annuler (remboursé : 3.000 TND) » → solde 6.000. Réserver de nouveau le menu 1 → solde 3.000.
  5. Vendredi (3.500 TND) : « Solde insuffisant », boutons désactivés.
  6. « Mon solde » : l'historique avec le solde après chaque mouvement (dont « Solde remis à 15 TND » avant la semaine).

Caissier — Caisse et encaissements

  1. « Caisse » : rechercher « employe » → « 10 TND » → « Enregistrer » → confirmer → solde 13.000 (notification « Solde rechargé »).
  2. Retour employé : réserver vendredi → solde 9.500.
  3. « Encaissements » (« Mon encaissement du jour ») : 1 recharge, « Argent à remettre » 10.000 TND. « Imprimer » → la feuille de remise (chaque recharge, total, montant compté, deux signatures).
  4. Le caissier n'a ni « Scanner » ni « Liste du jour ».

Scanner — Liste du jour

  1. « Liste du jour » : les réservations de mardi (menu, statut, heure de service), puis mercredi ; filtres, recherche, « Exporter (CSV) ».
  2. Le scanner n'a ni « Caisse » ni « Encaissements » (ouvrir /cashier ramène aux menus).

Direction

  3. « Finalisation » : réservations par menu ; « Prix du jour » de samedi modifiable.
  4. « Rapports » : présence par employé du mois (Réservés = Servis + Absences + Pas encore servis) ; cliquer un employé pour voir ses jours.

Fin des tests

Refaire les tests une autre fois

Une semaine de test ne sert qu'une fois. Pour recommencer, construire la semaine suivante :

backend\.venv\Scripts\python.exe backend\manage.py demo_week --monday 2026-12-07

Tout se passe de la même façon sept jours plus tard : ajouter 7 jours à chaque date des commandes (2026-12-08 20:30, 2026-12-09 08:30…) et prendre un autre matricule libre pour Sarra (ex. EMP-3012). Le solde de départ (6.000 TND) et les deux inscriptions en attente sont remis à l'identique.
