Guide d'installation
sur une VM Windows

Préparer la VM de l'application Cantine sous Hyper-V sur un PC, la déplacer sur le serveur de l'entreprise, puis l'ouvrir sur Internet — de A à Z

Version du 9 novembre 2026 · état d'avancement au 10 novembre 2026 (page suivante) · code : github.com/ahmeds1001/app-canteen (branche main)
Public : la personne qui prépare la VM et l'équipe IT. Durée : environ 3 heures sur le PC, 1 heure sur le serveur, plus les délais de l'IT (nom de domaine, certificat, SMTP).
Documents liés : dossier technique (docs/architecture-technique.pdf), cahier des charges (docs/cahier-des-charges.pdf).

Quatre règles avant de commencer

  1. Une VM neuve, avec un Windows neuf — jamais une copie du PC de développement : il contient des comptes de test, de fausses réservations, des mots de passe de test et une horloge de test.
  2. Une base de données vide : la production démarre sans aucun employé, menu, réservation ni solde. Le seul compte créé à l'installation est celui de l'administrateur (§8). Les commandes de données de test (demo_week, loadtest_accounts) ne sont jamais lancées sur cette base.
  3. Un fichier .env neuf, avec des secrets neufs (§7) — jamais celui du PC de développement. Il suit ensuite la VM partout (serveur, hébergeur) sans être changé.
  4. Un seul nom pour toujours (ex. cantine.ovagri.tn), du pilote interne jusqu'à Internet : changer de nom obligerait chaque employé à réinstaller l'application et à réactiver les notifications.

§6 sur un Windows français : la commande qui a fonctionné

Le nom NT AUTHORITY\SYSTEM n'existe pas sur un Windows français. Cette commande trouve le compte par son identifiant (le même dans toutes les langues) :

sqlcmd -S localhost\SQLEXPRESS -E -d canteen -Q "DECLARE @n sysname, @s nvarchar(400); SET @n = (SELECT name FROM sys.server_principals WHERE sid = 0x010100000000000512000000); IF @n IS NULL BEGIN RAISERROR('SYSTEM login missing', 16, 1); RETURN; END; PRINT 'Login: ' + @n; IF USER_ID(@n) IS NULL BEGIN SET @s = N'CREATE USER ' + QUOTENAME(@n) + N' FOR LOGIN ' + QUOTENAME(@n); EXEC(@s); END; SET @s = N'ALTER ROLE db_owner ADD MEMBER ' + QUOTENAME(@n); EXEC(@s);"

0. Vue d'ensemble

Les 3 phases

PhaseOùCe qu'on fait
A. PréparerUne VM Hyper-V sur le PC de la personne qui installe Windows, logiciels, application, base vide, administrateur, démarrage automatique, sauvegardes. Personne n'utilise l'application à ce stade. On exporte la VM propre.

Ce qui tourne dans la VM

Pas de Docker : deux programmes tournent en permanence, démarrés par le Planificateur de tâches de Windows, et SQL Server Express garde les données dans la même VM. Le proxy HTTPS de l'entreprise reçoit les connexions des téléphones et les transmet à la VM en HTTP sur le port 8080.

2. Créer la VM et préparer Windows

PHASE A — SUR LE PC

2.1 Activer Hyper-V sur le PC

PowerShell en tant qu'administrateur sur le PC, puis redémarrer le PC :

Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

2.2 Le réseau de la VM sur le PC

Sur le PC, la VM a seulement besoin d'Internet (pour installer les logiciels). On utilise le commutateur « Default Switch » créé par Hyper-V : rien à régler. Le vrai réseau sera branché sur le serveur (§13).

2.3 Créer la VM

Copier l'ISO de Windows Server dans C:\ISO\WindowsServer2022.iso, puis, toujours en PowerShell administrateur sur le PC :

# Versions de VM que le PC sait créer (comparer avec celle donnée par l'IT pour le serveur, §1)
Get-VMHostSupportedVersion
# Créer la VM (génération 2). Si le serveur est PLUS ANCIEN que le PC, ajouter -Version <version du serveur>, ex. -Version 9.0
New-Item -ItemType Directory -Force C:\HyperV
New-VM -Name "CANTINE-APP" -Generation 2 -MemoryStartupBytes 4GB -SwitchName "Default Switch" -Path C:\HyperV `
  -NewVHDPath "C:\HyperV\CANTINE-APP-C.vhdx" -NewVHDSizeBytes 60GB
Set-VMProcessor CANTINE-APP -Count 4
Set-VMMemory CANTINE-APP -DynamicMemoryEnabled $false
# Second disque pour les sauvegardes (D:)
New-VHD -Path "C:\HyperV\CANTINE-APP-D.vhdx" -SizeBytes 20GB -Dynamic
Add-VMHardDiskDrive -VMName CANTINE-APP -Path "C:\HyperV\CANTINE-APP-D.vhdx"
# Démarrer sur l'ISO de Windows
Add-VMDvdDrive -VMName CANTINE-APP -Path "C:\ISO\WindowsServer2022.iso"
Set-VMFirmware CANTINE-APP -FirstBootDevice (Get-VMDvdDrive -VMName CANTINE-APP)
Set-VM CANTINE-APP -AutomaticStartAction Start -AutomaticStopAction ShutDown -CheckpointType Standard
Start-VM CANTINE-APP; vmconnect.exe localhost CANTINE-APP

Si le PC a peu de mémoire, mettre pour l'instant -Count 2 et -MemoryStartupBytes 3GB : l'IT remettra 4 vCPU / 4 Go sur le serveur (§13). La version d'une VM ne se baisse pas après coup : la choisir maintenant.

2.4 Installer Windows dans la VM

  1. Dans la fenêtre de la VM, appuyer sur une touche dès « Press any key to boot from CD or DVD ».
  2. Choisir Windows Server 2022 Standard (Expérience de bureau), entrer la clé de licence, installation « Personnalisée » sur le disque de 60 Go.
  3. Choisir un mot de passe Administrateur fort (gardé dans le coffre de l'IT).
  4. Une fois Windows installé, retirer l'ISO depuis le PC (sinon le lecteur DVD prend la lettre D:) :
Get-VMDvdDrive -VMName CANTINE-APP | Remove-VMDvdDrive     # sur le PC

2.5 Préparer Windows (dans la VM)

Dans la VM, PowerShell en tant qu'administrateur :

# Disque de sauvegardes en D:
Get-Disk | Where-Object PartitionStyle -eq "RAW" | Initialize-Disk -PartitionStyle GPT -PassThru |
  New-Partition -DriveLetter D -UseMaximumSize | Format-Volume -FileSystem NTFS -NewFileSystemLabel "Sauvegardes"
# Fuseau horaire de Tunis et heure synchronisée (les délais de réservation se jouent à la minute)
Set-TimeZone -Id "W. Central Africa Standard Time"
w32tm /resync
# Ne jamais mettre la VM en veille
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
# Nom de la machine, puis redémarrer
Rename-Computer -NewName "CANTINE-APP" -Restart
  • Windows Update : installer les mises à jour maintenant, puis régler les redémarrages automatiques la nuit (ex. 03:00), jamais entre 11:00 et 15:00 (service) ni entre 20:00 et 00:30 (rush des réservations avant la clôture).
  • Vérifier que l'heure affichée est l'heure de Tunis (Get-Date) — une VM à l'heure fausse ferme les réservations au mauvais moment.

6. Créer la base de données

Les deux programmes de l'application tournent sous le compte SYSTEM de Windows (tâches planifiées, §10). On donne à ce compte, et à lui seul, les droits sur une base dédiée canteen. Dans PowerShell administrateur :

sqlcmd -S localhost\SQLEXPRESS -E -Q "CREATE DATABASE canteen"
sqlcmd -S localhost\SQLEXPRESS -E -d canteen -Q "IF SUSER_ID('NT AUTHORITY\SYSTEM') IS NULL CREATE LOGIN [NT AUTHORITY\SYSTEM] FROM WINDOWS; CREATE USER [NT AUTHORITY\SYSTEM] FOR LOGIN [NT AUTHORITY\SYSTEM]; ALTER ROLE db_owner ADD MEMBER [NT AUTHORITY\SYSTEM];"

Le compte Windows qui a installé SQL Server Express en est administrateur : c'est lui qui lance manage.cmd à la main dans les étapes suivantes. Pour un autre compte, refaire la seconde commande en remplaçant NT AUTHORITY\SYSTEM par son nom (whoami l'affiche).

Avec SQL Server Management Studio 20 (au lieu de sqlcmd)

  1. Connexion : Nom du serveur localhost\SQLEXPRESS ; Authentification Windows ; Chiffrement Obligatoire et cocher « Faire confiance au certificat de serveur » (SQL Server Express utilise un certificat auto-signé : sans cette case, SSMS 20 refuse la connexion).
  2. Nouvelle requête, coller puis exécuter (F5) :
CREATE DATABASE canteen;
GO
USE canteen;
IF SUSER_ID('NT AUTHORITY\SYSTEM') IS NULL CREATE LOGIN [NT AUTHORITY\SYSTEM] FROM WINDOWS;
CREATE USER [NT AUTHORITY\SYSTEM] FOR LOGIN [NT AUTHORITY\SYSTEM];
ALTER ROLE db_owner ADD MEMBER [NT AUTHORITY\SYSTEM];

SSMS sert aussi pour la suite : requêtes et modifications par l'administrateur (§17, encadré « Accès à la base »), test de restauration (§16.1 : clic droit sur Bases de données → Restaurer la base de données, sous le nom canteen_restore_test).

Variante : la base est sur un serveur SQL Server de l'entreprise

Vérifier d'abord la version du serveur dans SSMS (SELECT @@VERSION) : il faut SQL Server 2019 ou plus récent (version 15.x ou plus). La version de SSMS (20) ne dit rien sur celle du serveur. Créer ensuite une base canteen et un login SQL qui n'a des droits que sur elle (jamais sur l'ERP) :

CREATE DATABASE canteen;
CREATE LOGIN canteen_app WITH PASSWORD = '<mot de passe long>', CHECK_POLICY = ON;
USE canteen;
CREATE USER canteen_app FOR LOGIN canteen_app;
ALTER ROLE db_owner ADD MEMBER canteen_app;

Puis, au §7, remplir DB_HOST, DB_PORT=1433, DB_USER=canteen_app et DB_PASSWORD. Les sauvegardes (§11) sont alors faites par l'équipe SQL Server avec ses outils habituels.

7. Écrire le fichier .env

Le fichier C:\cantine\.env contient tous les réglages et secrets du serveur. Il n'est jamais envoyé sur GitHub ni copié depuis un autre PC. Générer d'abord les secrets :

cd C:\cantine\backend
# à lancer deux fois : une valeur pour DJANGO_SECRET_KEY, une autre pour CANTEEN_SIGNING_KEY
.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(64))"
# clés des notifications push
.venv\Scripts\python.exe manage.py generate_vapid_keys

Créer C:\cantine\.env avec le Bloc-notes (encodage UTF-8) et ce contenu, en remplaçant les valeurs entre < >. Le nom est déjà le nom définitif (règle 4), même si la VM est encore sur le PC :

DJANGO_DEBUG=false
DJANGO_SECRET_KEY=<première valeur générée>
CANTEEN_SIGNING_KEY=<seconde valeur générée>
DJANGO_ALLOWED_HOSTS=cantine.ovagri.tn
CSRF_TRUSTED_ORIGINS=https://cantine.ovagri.tn
CORS_ALLOWED_ORIGINS=https://cantine.ovagri.tn
FRONTEND_URL=https://cantine.ovagri.tn
COMPANY_TIME_ZONE=Africa/Tunis
# La VM sert aussi les pages du site ; un seul proxy devant elle
SERVE_FRONTEND=true
NUM_PROXIES=1

# --- Base de données (SQL Server Express dans la VM, authentification Windows) ---
DB_ENGINE=mssql
DB_NAME=canteen
DB_HOST=localhost\SQLEXPRESS
DB_PORT=
DB_USER=
DB_PASSWORD=
DB_ODBC_DRIVER=ODBC Driver 18 for SQL Server

# --- Emails ---

EMAIL_HOST_PASSWORD=<mot de passe SMTP>

# --- Notifications push (les 2 lignes affichées par generate_vapid_keys) ---

Point d'attentionPourquoi
DB_PORT, DB_USER, DB_PASSWORD videsVide = instance nommée SQLEXPRESS et connexion Windows (compte SYSTEM). Avec un login SQL, les remplir (§6, variante).
Pas de DEV_SEED_PASSWORD, pas de THROTTLE_LOGINRéservés au PC de développement et au test de charge. En production, la connexion est limitée à 10 essais par minute et par personne.
CANTEEN_SIGNING_KEYSigne les QR codes. La changer plus tard rend invalides les QR déjà affichés.
Clés VAPIDLes changer plus tard oblige chaque téléphone à réactiver les notifications.
Droits sur le fichierLimiter .env aux administrateurs et à SYSTEM (clic droit → Propriétés → Sécurité). En garder une copie dans le coffre de mots de passe de l'IT.

createsuperuser demande l'email professionnel, le prénom, le nom et le mot de passe (deux fois). Ce compte a le rôle Admin dans l'application. Choisir une vraie adresse de l'entreprise et un mot de passe long, gardé dans le coffre de l'IT.

check --deploy ne doit afficher que des remarques sur SECURE_HSTS_INCLUDE_SUBDOMAINS / SECURE_HSTS_PRELOAD (choix volontaire). Toute autre alerte : revoir le fichier .env.

La production démarre vide — et c'est voulu

  • Après ces commandes, la base ne contient aucun employé, plat, menu, réservation, solde ni historique. Le seul compte est l'administrateur.
  • Les employés créent eux-mêmes leur compte depuis l'écran « Créer un compte », puis les RH les valident (le matricule est saisi par les RH).
  • Les comptes de test du PC de développement (…@ovagri.test) n'existent pas ici et ne doivent pas être recréés.
  • demo_week refuse de fonctionner en production ; loadtest_accounts refuse toute base dont le nom ne contient pas « loadtest ». Ne pas essayer de les contourner.

9. Premier démarrage à la main

C:\cantine\setup\windows\run-site.cmd contient deux lignes à adapter :

set PORT=8080
set PROXY_IP=192.168.1.10      # adresse du proxy HTTPS de l'entreprise

Tant que la VM est sur le PC, ne rien changer : il n'y a pas encore de proxy, et la vraie adresse se met sur le serveur (§14). Lancer run-site.cmd (double-clic), puis dans PowerShell :

Invoke-RestMethod http://localhost:8080/api/v1/health/
# attendu : status = ok, database = ok, server_time = l'heure de Tunis
Get-Content C:\cantine\logs\site.log -Tail 20

En HTTP direct, toutes les autres adresses répondent par une redirection vers https : c'est normal, le site complet ne s'ouvre qu'à travers le proxy (phase B). Fermer ensuite la fenêtre de run-site.cmd.

Faire de même avec run-tasks.cmd : sa fenêtre reste ouverte sans message, et C:\cantine\logs\tasks.log ne doit pas contenir d'erreur. Le fermer aussi.

10. Démarrage automatique au boot

Trois tâches du Planificateur de tâches, sous le compte SYSTEM, qui tournent même sans session ouverte. Dans PowerShell administrateur :

$dir  = "C:\cantine\setup\windows"
$sys  = New-ScheduledTaskPrincipal -UserId "SYSTEM" -LogonType ServiceAccount -RunLevel Highest
$keep = New-ScheduledTaskSettingsSet -ExecutionTimeLimit ([TimeSpan]::Zero) -AllowStartIfOnBatteries `
          -DontStopIfGoingOnBatteries -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask -TaskName "Cantine - Site" -Principal $sys -Settings $keep `
  -Trigger (New-ScheduledTaskTrigger -AtStartup) `
  -Action (New-ScheduledTaskAction -Execute "$dir\run-site.cmd" -WorkingDirectory $dir)

Register-ScheduledTask -TaskName "Cantine - Taches" -Principal $sys -Settings $keep `
  -Trigger (New-ScheduledTaskTrigger -AtStartup) `
  -Action (New-ScheduledTaskAction -Execute "$dir\run-tasks.cmd" -WorkingDirectory $dir)

Register-ScheduledTask -TaskName "Cantine - Sauvegarde" -Principal $sys `
  -Trigger (New-ScheduledTaskTrigger -Daily -At 02:00) `
  -Action (New-ScheduledTaskAction -Execute "$dir\backup.cmd" -WorkingDirectory $dir)

Start-ScheduledTask "Cantine - Site"; Start-ScheduledTask "Cantine - Taches"
Get-ScheduledTask "Cantine*" | Select-Object TaskName, State     # Site et Taches : Running
  • run-site.cmd et run-tasks.cmd relancent eux-mêmes le programme 10 secondes après un arrêt.
  • « Cantine - Taches » ne doit tourner qu'en un seul exemplaire : ne jamais lancer en plus run-tasks.cmd à la main.
  • Redémarrer la VM une fois et vérifier que les deux tâches repassent à Running et que le contrôle de santé répond.

11. Sauvegardes

backup.cmd fait chaque nuit une sauvegarde vérifiée de la base (canteen_AAAAMMJJ_HHMM.bak) et une copie des photos des plats (media_AAAAMMJJ_HHMM). Il ne supprime jamais rien.

# 1. Créer le dossier et autoriser le service SQL Server à y écrire

# 3. Essai immédiat

À organiser par l'IT (une fois sur le serveur)

  • Copier chaque jour D:\CantineBackups hors de la VM (partage réseau, autre serveur) — une sauvegarde qui reste dans la VM ne protège pas contre la perte de la VM.
  • Décider combien de temps garder les fichiers et supprimer les plus anciens sur la copie (environ 1 à 5 Mo par jour au départ).
  • Garder aussi le fichier C:\cantine\.env dans le coffre de l'IT : sans lui, on ne relit pas les QR codes et les notifications s'arrêtent.

13. Importer la VM sur le serveur

PHASE B — SUR LE SERVEUR DE L'ENTREPRISE

Sur le serveur Hyper-V (IT), PowerShell administrateur — ou le Gestionnaire Hyper-V → Importer un ordinateur virtuel → Copier l'ordinateur virtuel (créer un nouvel ID unique) :

  • Si le serveur n'est pas Hyper-V (VMware…) : convertir le disque .vhdx avec l'outil de l'éditeur, ou installer directement sur le serveur en suivant ce guide (environ 3 heures).
  • Dans la VM, vérifier l'activation de Windows (slmgr /xpr) : un changement de machine peut demander de réactiver la licence.
  • Vérifier l'heure : Get-Date doit afficher l'heure de Tunis.

14. Les adresses : IP de la VM, IP du proxy, pare-feu

Sur le serveur, deux adresses changent. Elles viennent toutes les deux de l'IT (§1) :

Adresse IP de la VMAdresse du proxy (PROXY_IP)
De qui ?La VM elle-mêmeUne autre machine : le proxy HTTPS placé devant la VM
Ce qu'elle dit« J'habite ici »« Je n'accepte les demandes que de cette machine »
Qui s'en sertLe proxy, pour savoir où envoyer les employésL'application, pour savoir à qui faire confiance
Où la mettreRéglages réseau de Windows, dans la VM (§14.1)run-site.cmd (§14.2) et la règle du pare-feu (§14.3)

14.1 Donner son adresse fixe à la VM

  1. Dans la VM : Windows + R → taper ncpa.cpl → Entrée.
  2. Clic droit sur Ethernet → Propriétés → Protocole Internet version 4 (TCP/IPv4) → Propriétés.
  3. Choisir « Utiliser l'adresse IP suivante » et saisir ce que donne l'IT : adresse (ex. 192.168.1.50), masque (souvent 255.255.255.0), passerelle, serveurs DNS. Valider.
  4. Vérifier dans PowerShell : ipconfig affiche la nouvelle adresse ; Test-NetConnection github.com -Port 443 répond True.

14.2 Mettre l'adresse du proxy dans run-site.cmd

Ouvrir C:\cantine\setup\windows\run-site.cmd avec le Bloc-notes, changer la ligne et enregistrer :

set PROXY_IP=<adresse du proxy donnée par l'IT>

Pourquoi : la VM ne voit jamais le téléphone, seulement le proxy, qui ajoute à chaque demande une note « vient du téléphone X, en HTTPS ». L'application ne croit cette note que si elle vient de PROXY_IP — sinon n'importe qui pourrait la falsifier. Avec une mauvaise adresse : le navigateur affiche « trop de redirections », et après 10 essais de connexion dans toute l'entreprise, tout le monde est bloqué une minute.

14.3 Pare-feu : le port 8080 pour le proxy seulement

Dans la VM, PowerShell administrateur, avec la même adresse :

New-NetFirewallRule -DisplayName "Cantine 8080 (proxy seulement)" -Direction Inbound -Protocol TCP `
  -LocalPort 8080 -RemoteAddress <adresse du proxy> -Action Allow
# plus tard, si le proxy change d'adresse :
Set-NetFirewallRule -DisplayName "Cantine 8080 (proxy seulement)" -RemoteAddress <nouvelle adresse>

Aucun autre port n'est à ouvrir pour l'application (SQL Server reste dans la VM). Puis redémarrer la VM (Restart-Computer) pour que le site reparte avec la nouvelle adresse du proxy.

Si l'IT ne connaît pas l'adresse exacte du proxy

  1. Ouvrir le port 8080 quelques minutes, à tout le réseau interne : Set-NetFirewallRule -DisplayName "Cantine 8080 (proxy seulement)" -RemoteAddress Any
  2. Ouvrir https://cantine.ovagri.tn depuis un PC, puis dans la VM : Get-NetTCPConnection -LocalPort 8080 | Select-Object -Unique RemoteAddress — l'adresse affichée est celle du proxy.
  3. La mettre dans run-site.cmd (§14.2) et refermer le pare-feu sur elle (Set-NetFirewallRule … -RemoteAddress <adresse>), puis redémarrer la VM.

15. Nom de domaine, certificat et proxy HTTPS

  • Le nom : cantine.ovagri.tn pointe, dans le DNS interne de l'entreprise, vers le proxy. Plus tard, le DNS public pointera vers l'adresse publique (§19) — même nom, rien ne change pour les employés.

Restaurer la dernière sauvegarde sous un autre nom, pour ne pas toucher la vraie base :

16.2 Vérifications

  • https://cantine.ovagri.tn/api/v1/health/ → "status": "ok", "database": "ok", heure de Tunis.
  • Connexion avec le compte administrateur sur https://cantine.ovagri.tn ; le menu affiche « Paramètres ».
  • Création d'un compte depuis un téléphone : l'email de code arrive (sinon : réglages SMTP, §21).
  • Sur le téléphone : installer l'application (menu du navigateur → « Installer » ou « Ajouter à l'écran d'accueil »), puis activer les notifications ; une notification arrive (ex. validation du compte).
  • Le téléphone de la cantine ouvre « Scanner » et la caméra démarre (HTTPS indispensable).
  • Après une nuit : logs\backup.log indique une sauvegarde vérifiée, copiée hors de la VM ; logs\tasks.log sans erreur.
  • Redémarrage de la VM, puis du serveur : le site revient tout seul en moins de 2 minutes.

17. Premier paramétrage dans l'application

Avec le compte administrateur, avant d'ouvrir l'application aux employés :

  1. Paramètres : vérifier chaque valeur — clôture des réservations (jours + heure), délai de publication du chef, heure de finalisation, horaires du service, marge de plats (10 %), rappels, prix du repas, recharge minimum (20 TND), jours ouverts.
  2. Comptes du personnel : chaque personne (RH, chef, scanner, caissier, Direction) crée son compte depuis « Créer un compte » avec son email professionnel ; l'administrateur (ou les RH une fois validés) le valide dans Comptes, saisit le matricule et choisit le rôle. Un rôle par compte.
  3. Le chef remplit la bibliothèque de plats (avec photos) puis planifie les menus de la première semaine.
  4. Le téléphone de la cantine : se connecter avec le compte scanner, installer l'application, autoriser la caméra.
  5. Le caissier enregistre les premières recharges : le solde prépayé est le seul moyen de payer un repas.
  6. Ensuite seulement, annoncer l'adresse aux employés (email, affiche avec un QR code vers https://cantine.ovagri.tn).

Comptes à ne pas créer

Pas de comptes « de test », partagés ou génériques : chaque compte est nominatif, validé par les RH. Pour essayer l'application, utiliser le PC de développement, jamais la production.

Accès à la base de données (SSMS 20) — l'administrateur a tous les droits

L'administrateur peut consulter et modifier la base avec SSMS 20 : requêtes SELECT, UPDATE, INSERT… Pour des raisons de sécurité, la base n'est pas ouverte sur le réseau : on s'y connecte depuis la VM (Bureau à distance, puis SSMS : serveur localhost\SQLEXPRESS, authentification Windows, « Faire confiance au certificat de serveur »).

Le compte Windows qui a installé SQL Server a déjà tous les droits. Pour donner les mêmes droits sur la base canteen à un autre administrateur (remplacer DOMAINE\nom) :

CREATE LOGIN [DOMAINE\nom] FROM WINDOWS;
USE canteen;
CREATE USER [DOMAINE\nom] FOR LOGIN [DOMAINE\nom];
ALTER ROLE db_owner ADD MEMBER [DOMAINE\nom];     -- lecture + modification de toute la base canteen

Avant toute modification à la main :

  1. Lancer une sauvegarde : Start-ScheduledTask "Cantine - Sauvegarde" (et vérifier logs\backup.log).
  2. Travailler dans une transaction et vérifier le résultat avant de valider :
BEGIN TRANSACTION;
UPDATE ... WHERE ...;          -- toujours avec un WHERE précis
SELECT ... ;                   -- vérifier les lignes changées
COMMIT;                        -- ou ROLLBACK; pour tout annuler
  • Une modification faite dans SSMS n'apparaît pas dans le journal d'audit de l'application : la noter (date, qui, quoi, pourquoi) dans le registre de l'IT.
  • Quand l'application sait le faire, passer par elle : une correction de solde se fait par la Direction (elle garde l'historique du solde) ; un solde modifié directement dans la table ne correspondrait plus à ses mouvements.
  • Pas de DELETE : décision de l'entreprise, aucune donnée n'est supprimée (comptes, réservations, journal d'audit).

18. Pilote sur le réseau de l'entreprise

  • Les données du pilote sont réelles : comptes, soldes payés, réservations. On les garde pour la suite — on ne « repart pas de zéro » avant Internet, et on ne revient jamais au point de contrôle du §12.
  • Pilote : une à deux semaines avec un service ou un étage, en gardant l'ancienne organisation en secours ; noter les remarques, puis ouvrir à tous les employés.
  • Test de charge (200 utilisateurs simultanés, kit loadtest/ du dépôt) : sur une base séparée nommée canteen_loadtest et un .env distinct — jamais sur la base canteen. Le plus simple : avant l'ouverture aux employés, sur une copie de la VM importée à côté, puis supprimer cette copie.

19. Ouvrir l'application sur Internet

PHASE C — SUR INTERNET

Pour que les employés réservent depuis chez eux (4G, Wi-Fi personnel). Deux façons de faire avec l'hébergeur / le fournisseur :

CasCe qu'il faut faire
1. La VM reste sur le serveur de l'entreprise, le fournisseur donne un accès public Une adresse publique arrive sur le proxy HTTPS (port 443 seulement) ; le DNS public de cantine.ovagri.tn pointe dessus. Rien ne change dans la VM si c'est le même proxy. Si c'est un nouveau proxy : mettre sa nouvelle adresse (§14.2 et §14.3), puis redémarrer la VM.
2. La VM part chez l'hébergeur Prévoir une coupure un jour où la cantine est fermée : annoncer la coupure, lancer une sauvegarde (Start-ScheduledTask "Cantine - Sauvegarde"), arrêter la VM, l'exporter (§12.3 sans revenir au point de contrôle), l'importer chez l'hébergeur (§13), refaire les adresses (§14), faire pointer le DNS vers l'hébergeur, vérifier (§16.2). Même .env : les QR codes, les connexions et les notifications continuent de marcher.

Sécurité : ce qui doit être vrai avant d'ouvrir sur Internet

  • Seul le port 443 du proxy est ouvert sur Internet. Le port 8080 de la VM, le bureau à distance (RDP, 3389) et SQL Server (1433) ne le sont jamais — l'administration de la VM passe par le VPN de l'entreprise ou de l'hébergeur.
  • La page technique /admin/ (Django) est limitée sur le proxy aux adresses de l'entreprise ; l'application elle-même (y compris l'écran « Paramètres ») reste accessible.
  • Windows Update chaque mois, en dehors du service et du rush du soir ; mot de passe fort pour le compte administrateur de l'application et de Windows.
  • Sauvegardes copiées hors de chez l'hébergeur (ou hors du serveur), restauration testée (§16.1).
  • Surveillance : l'IT ou l'hébergeur vérifie https://cantine.ovagri.tn/api/v1/health/ chaque minute et reçoit une alerte s'il ne répond plus ok.
  • Données personnelles des employés (noms, emails, matricules, soldes) : le contrat avec l'hébergeur doit dire où elles sont stockées et qui y a accès ; vérifier avec la Direction les obligations de déclaration (INPDP).

Si l'hébergeur propose un serveur Linux, la version Docker décrite dans le dossier technique est aussi possible : on y reprend la sauvegarde de la base (SQL Server sous Linux restaure le même fichier .bak), le dossier des photos et le même .env.
